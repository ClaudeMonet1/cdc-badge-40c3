# Files

- [BLE GATT for plugins](ble-gatt-for-plugins.md) - The plugin-facing Bluetooth LE API of cdc-badge-os — one reserved GATT server service (up to 6 characteristics) plus the central/client role, single connection, 244-byte payloads, 4-deep write/notify rings drained on the plugin tick task, reserved-UUID refusal, and the single-controller constraints (service registration restarts NimBLE) from ADR-0008.
- [Canvas, surfaces, sprites and animation](canvas-surfaces-and-animation.md) - How a plugin draws custom screens on cdc-badge-os — the CanvasView retained display list (128 commands, text/bitmap/sprite arenas), named elements for cheap animation, inline widgets, fonts, off-screen surfaces, sprites, host-driven tweens capped at 5 fps, refresh policies and the view/modal stack limits.
- [Hardware I/O for plugins: GPIO, PWM, ADC, I2C, SAO, pixel strip](hardware-io-for-plugins.md) - Runtime semantics of plugin hardware access on cdc-badge-os — the three-layer check (manifest, pin lock, firmware block list), pin locks shared with the GPIO serial shell, LEDC PWM channels sharing one timer, ADC1 one-shot reads, I2C restricted to the expansion bus, the SAO EEPROM, the shared WS281x/SK6812 pixel strip, and release on unload.
- [Host API (ABI) reference](host-api-reference.md) - The C ABI that cdc-badge-os exposes to WASM plugins — 307 host_* functions imported from WAMR module "cdc", grouped by family with the capability each needs, calling conventions (pointers, wasm32 length-returning forms, UTF-8), return codes, API level 0.8 compatibility rules, and how the canonical header is mirrored into the SDK.
- [Inter-plugin external features](inter-plugin-features.md) - The cdc-badge-os "Open with" mechanism that lets one plugin hand a job to another — providers declaring `provides` and registering handlers in plugin_init, callers using host_ext_feature_use with a ≤32 KiB payload, the single job slot, foreground switch on the tick task, consume-once payloads, result routing back to the caller, and the limits and pitfalls.
- [Plugin lifecycle, events and UI](lifecycle-events-and-ui.md) - The exports a cdc-badge-os WASM plugin must and may provide, the load→init→prerequisites→enter→exit→deinit sequence, foreground/background/autoload residency, the 50 ms plg_tick task, action-id callbacks and EventBus delivery, trap handling, and the three UI styles (prebuilt views, canvas, low-level GFX) plus lock-screen hooks.
- [Plugin manifest, capabilities and sandbox security](manifest-and-capabilities.md) - The meta.json manifest of a cdc-badge-os plugin (fields, i18n, capabilities, prerequisites), how capabilities are validated at load and enforced per host call, per-plugin storage isolation (NVS, vFAT, secure element), the GPIO policy, the absence of plugin signing, and the resulting threat model for our Rust WASM application.
- [Networking for plugins: Wi-Fi, HTTP, sockets, listener](networking-wifi-http-sockets.md) - What a cdc-badge-os plugin actually gets from the wifi, http, socket and net_listen capabilities — hold-counted Wi-Fi shared with prerequisites (timeout argument ignored), 4 HTTP slots with whole-body PSRAM buffering up to 1 MiB, TLS via the ESP-IDF certificate bundle and a per-origin keep-alive pool, 8 TCP/UDP sockets without TLS, an inbound listener with backlog 4, and SNTP time sync that TLS and TOTP-style plugins depend on.
- [WAMR plugin runtime](wamr-runtime.md) - How cdc-badge-os embeds the WebAssembly Micro Runtime — build features (fast interpreter, AOT compiled but rejected, ref-types, bulk memory, no WASI), the PSRAM allocator, how a plugin binary is loaded and instantiated (64 KiB stacks, heap 0 for Rust), per-call instruction metering, trap semantics, and the concrete constraints this puts on Rust wasm32 output.
