# Files

- [cdc-badge-os architecture](architecture.md) - Layered structure of the cdc-badge-os reference firmware (ESP-IDF on ESP32-S3) — components, the staged boot in main.cpp, the cooperative main loop, service and module registries, EventBus, UI stack, feature modules, the PSRAM-first memory rule and the no-migration policy — and where the WASM plugin system fits.
- [Encrypted backup and restore](backup-and-restore.md) - The cdc-badge-os .cdcbak backup — PBKDF2-SHA256 (200k) + AES-256-GCM container with an authenticated header, the JSON payload of semantic records from mod_2fa, mod_password, mod_vcard and system settings, restore semantics, the backup.py companion tool, and what is never backed up (FIDO2/GPG keys and all plugin data).
- [OS build, partitions and flashing](build-flash-and-partitions.md)
- [I18n and language overlays](i18n-and-language-overlays.md) - How cdc-badge-os localises strings — compiled-in English tables, flat lang_<code>.json overlay files in /vfat/system/i18n converted from UTF-8 to CP437, per-plugin translations from the manifest and <id>.lang.json files, the host_i18n_* calls, and the limitation that the plugin language API only distinguishes English and German.
- [Writing an OS module](module-development.md) - How native cdc-badge-os feature modules are built — ModuleBase/IModule lifecycle, the single MODULES registration point and generated registration header, the boot order (init all, then start the enabled set from module_defaults.h and NVS), and the checklist — plus when a native module is the right choice instead of a WASM plugin.
- [Production hardening and provisioning](production-hardening.md) - The opt-in, irreversible lockdown flow for a CDC Badge running cdc-badge-os — why stock badges are open (public TROPIC01 pairing key, no secure boot or flash encryption, open download mode), the disarmed provision.py tool with its guards and per-chip manifests, TROPIC01 pairing-key rotation, the cdc_badge_release build, the ESP32-S3 eFuse state machine, and what it changes for plugins.
- [Serial console and authentication](serial-console-and-auth.md) - The cdc-badge-os serial console (serial_cmd) over USB CDC, UART and BLE UART — per-transport AUTH sessions with a 5-minute timeout, the effective secure-serial default (on in the shipped sdkconfig despite the header fallback), which commands need no PIN, and a catalogue of the command groups relevant to plugin development and security.
- [Storage tools: MSC, vFAT and NVS editor](storage-tools.md) - The cdc-badge-os storage modules — mod_vfat file explorer and VFAT serial shell over the 2 MB FAT partition, mod_msc USB mass storage (unlocked-only, exposes /vfat/system unless FEATURE_PLUGIN_SYSTEM_LOCK, blocks badge-side writes while mounted), and the read-only-by-default NVS browser — and what they mean for plugin storage, backups and the unsigned plugin install path.
- [USB stack and smartcard (CCID)](usb-stack-and-smartcard.md) - How cdc-badge-os presents itself over USB — a TinyUSB composite device (CDC serial plus optional FIDO HID, keyboard HID, OTP HID, CCID and MSC) managed by UsbServiceManager under the ESP32-S3's 4-IN/6-OUT endpoint budget, the VID/PID identities it switches between (Gemalto for libccid, Espressif, OnlyKey), and the CCID applet router hosting OpenPGP, OATH and PIV.
